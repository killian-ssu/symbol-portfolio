# 同类倍率与牌型揭示动效设计

日期：2026-07-17

## 背景与目标

当前运行时配置中，双同类、三同类、四同类、五同类的基础倍率分别是 `2/2/3/5`；倍率区使用累计滚分动效；牌型图片则是静态开关显示。

本次要达成：

1. 同类张数与基础倍率一致：双同类 ×2、三同类 ×3、四同类 ×4、五同类 ×5。
2. 保留现有“双同类/三同类/四同类/五同类”图片，让图片使用行动格分数同款的跳出、上浮和淡出节奏，播放后隐藏。
3. 第 2/3/4 张伙伴牌使同类牌型发生变化时各播放一次；第 5 张的最终牌型无论是否与上一次预览相同，都强制再播放一次。
4. 倍率数字立即替换为新值，只播放原有数值弹跳，不再滚分。
5. 结算期刷新锁等已有交互保持不变。

## 方案选择

采用“共享分数爆字播放器”方案：把 `FloatingTextComp.playScoreBurst` 现有的节奏执行提取为可复用播放器，浮动分数和牌型图片都使用同一个 `ScoreBurstMotionProfile` 和同一份播放逻辑。

不采用以下方案：

- 在 HUD 内复制一份 Tween：初始改动小，但会与行动格分数逐渐分叉。
- 临时复制牌型节点播放：需要额外管理节点销毁、图片帧和层级，更容易残留状态。

## 规则与真相源

`assets/resources/config/gameplay/patterns.json` 继续是牌型名称、优先级和倍率的唯一运行时真相源。只修改 `three_same` 和 `four_same` 的 `multiplier`，保留稳定 ID、优先级和判定条件。

| 牌型 ID | 玩家名称 | 基础倍率 |
|---|---|---:|
| `two_same` | 双同类 | 2 |
| `three_same` | 三同类 | 3 |
| `four_same` | 四同类 | 4 |
| `five_same` | 五同类 | 5 |
| `junk` | 散牌 | 1 |

道具提供的固定或当轮倍率加成仍由 Core 在基础倍率上累加，UI 不重复计算。

## 牌型图片动效

### 共享播放器

新增一个只管理自己 Tween 的共享分数爆字播放器。它接收：

- 要动画的 `Node`；
- 已在 Prefab 中绑定的 `UIOpacity`；
- 由 `UIMotionPresetLibraryComp` 解析的 `ScoreBurstMotionProfile`；
- 强度、左右方向与完成回调。

播放器负责缩放、旋转、上浮、水平漂移与淡入/淡出。`FloatingTextComp` 播放行动格分数时，在完成回调中销毁临时浮字节点；牌型图片播放时，在完成回调中恢复 Prefab 基准位置/缩放/角度/透明度并隐藏节点，不销毁现有图片节点。

牌型图片每次揭示时通过现有 `pickRotationDirection` 选择一个左右方向，并以强度 `1` 播放一次；不使用连击强度递增。

### Prefab 绑定

在 `game_main.prefab` 现有 `Pattern` 节点上增加 `UIOpacity` 和专用的牌型揭示组件，不新增视觉节点，不替换 SpriteFrame、颜色、尺寸或布局。组件持有：

- 现有 `Pattern` 节点作为动画目标；
- 节点的 `UIOpacity`；
- 稳定预设 ID `score_cell_combo_burst_v1`。

所有幅度、旋转、时长、上浮距离和淡出节奏仍从 `ui_motion_library.prefab` 读取，运行时不覆盖 Inspector 参数。

### 播放时机

- 预览：行动格中已有伙伴牌、且 Core 返回的同类牌型 ID 相较上一次发生变化时，播放新牌型图片。因此双同类、三同类、四同类可在第 2/3/4 张各播放一次。
- 稳定性：同一牌型只是倍率被道具修正时，不重播图片；新牌型在旧动画完成前到来时，先取消旧 Tween 并恢复基准状态，再播放新图片。
- 最终结算：第 5 张伙伴牌返回最终结果后，对同类牌型强制再播放一次，不受“与上一次 ID 相同”的去重影响。`GameMainViewComp` 等待该动画完成后才开始逐格结算。
- 散牌：不属于“同类标签”，不触发本次新增的跳出消失动效。

若牌型揭示组件或透明度绑定缺失，预览降级为现有静态图片显示；最终结算则使用 `GameMainViewComp.settlementPatternRevealDelay` 的 Prefab 值等待后继续。缺少表现绑定不影响核心计分或阻断结算。

## 倍率区动效

`settlementMultMotion` 继续使用现有 `ScoreValueMotionComp`，但 `game_main.prefab` 中的 `presetId` 从 `score_value_roll_pop_v1` 改为 `score_setter_pop_video_v1`。

该预设的 `rollDuration` 为 `0`，因此倍率数字会立即显示目标值，仅保留缩放、旋转和回弹。结算分数和目标分继续使用原有滚分预设，不受影响。

## 数据流

1. Core 从 `patterns.json` 识别牌型并返回基础倍率。
2. `GameMainViewComp` 比较当前预览牌型 ID 与上一次 ID，只决定是否请求播放，不自行判定几同类。
3. `HudViewComp` 根据 Core 给出的 ID 选择已绑定 SpriteFrame，然后调用牌型揭示组件。
4. 牌型揭示组件从共享动效库取得 `score_cell_combo_burst_v1`，共享播放器对现有图片节点播放。
5. 倍率数字仍只消费 Core 返回的倍率，`ScoreValueMotionComp` 通过无滚分预设更新。

## 测试与验收

### 自动测试

- 权威配置断言五个启用牌型的基础倍率为 `5/4/3/2/1`（按优先级降序）。
- 核心牌型识别断言双/三/四/五同类分别返回 `2/3/4/5`。
- UI 契约断言预览只在同类牌型 ID 变化时请求播放，最终结算强制请求并等待完成。
- 动效契约断言浮动分数和牌型图片共用播放器与 `score_cell_combo_burst_v1`。
- Prefab 契约断言 `Pattern` 节点绑定透明度/揭示组件，倍率动效绑定 `score_setter_pop_video_v1`，分数与目标数值仍绑定原预设。
- 运行完整 Core/UI 契约、Prefab JSON 解析与 TypeScript 编译检查。

### Cocos 手工验收

1. 连续放下同种伙伴，第 2/3/4 张分别看到双/三/四同类图片跳出、上浮、淡出。
2. 第 5 张放下后再看到五同类图片，图片动画完成后才开始逐格结算。
3. 快速连续出牌时，旧图片不残留，新牌型从 Prefab 原始位置完整重播。
4. 倍率区在双/三/四/五同类时立即显示 `×2/×3/×4/×5`，只弹跳，不出现中间数值。
5. 结算期点击刷新仍无效，不消耗刷新次数。

## 范围边界

- 不替换现有牌型 SpriteFrame、图片尺寸、颜色、层级或锚点。
- 不改动行动格计分节奏、道具触发顺序、总分公式或倍率加成逻辑。
- 不新建弹窗或全屏遮罩。
- 不解决当前工作区中与本需求无关的 `board_cell.prefab` 绑定或动效契约断言问题。
