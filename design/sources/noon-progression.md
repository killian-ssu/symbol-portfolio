# 局外成长与商城设计

2026-11-13 · 第一版协作稿。[返回整体设计](../docs/noon-system-overview.html)。本稿按当前正式入口、服务与配置整理，使用现行备战三页及商城；后续 v2.1 的碎片、升星、五十级树与新奖池单列，不混为已完成。以下“实现”指源码可核对，本轮未运行游戏或交易。

## 1. 系统约束与资源关系

备战分为强化、皮肤库、技能。进程内记住最后查看的备战页，新开默认强化。长期成长与本局选卡各自保存；出击时将攻击、技能成长和规则组成本局快照，不能在途中通过更换长期成长改写原局。

| 资源/状态 | 现行主要用途 | 关联入口 |
| --- | --- | --- |
| 金币 | 强化与永久技能升级 | 战斗结算、每日及礼包；灵晶兑换 |
| 强化石 | 当前四级强化 | 首四星首通与见面礼等现行奖励 |
| 专属/通用技能材料 | 爆破、穿透、导弹永久升级 | 既有库存和符合阶段的现行奖励；部分旧购买入口当前隐藏 |
| 灵晶 | 金币兑换、体力、复活等现行消耗 | 首通、每日、充值和礼包等 |
| 已拥有装备/外观与穿戴 ID | 决定整套可穿、实际外观和可生效属性 | 通关、武装整备、同行证 |

永久强化、技能升级与穿戴要求没有未结束挑战。普通账号操作通过 `TryAccountTransaction`：修改前保存内存快照，改动与落盘均成功后才展示成功；拒绝或保存失败恢复原状态。购买履约有单独的已验证订单保存和重试流程，不能简单套用金币消费的处理。

各项结算资源的发放条件、到账时点及复活边界见[结算规格](../docs/noon-settlement.html)；局内词条与永久成长的叠加关系见[选卡规格](../docs/noon-cards.html)。

## 2. 强化系统

当前作用是把首段通关收益转成下一星可感知的攻击。此目标由现有首测范围支持；长期五十级成长另见后续设计。

| 检查项 | 现行规格 |
| --- | --- |
| 怎么触发 | 进入备战“强化”，点击当前可升节点/升级操作 |
| 什么条件 | 无进行中的挑战；等级低于 `min(已通关星数,4)`；金币和强化石均足够 |
| 如何记录 | 账号保存当前强化等级、金币、强化石；界面读取真实总攻击与下级增量 |
| 结果与反馈 | 同一次操作扣两种资源并提升一级；成功后刷新等级、攻击和余额，再展示强化成功反馈 |
| 特殊情况 | 未达通关门槛、材料不足、金币不足、已满四级、挑战未结束均需区分；旧档已投入攻击可能使本次显示增量小于新档 +2，不强写固定成功数值 |
| 保存数据 | 等级与扣款一起保存；失败整体恢复。旧力量与旧槽位投入按现行兼容取较高收益，不重复叠加 |
| 配置 | `campaign.json.firstChapterGrowth` 的攻击增量、金币、材料和首通发放表；当前四级上限还由 `FirstChapterGrowthConfig.Ranks` 约束 |

| 升到等级 | 金币 | 强化石 | 新档累计强化攻击 |
| --- | --- | --- | --- |
| 1 | 120 | 1 | +2 |
| 2 | 150 | 2 | +4 |
| 3 | 200 | 2 | +6 |
| 4 | 260 | 3 | +8 |

首四星首通分别发 1、2、2、3 个强化石。新档未计外观时总攻击为 `1 + 2×强化等级`；旧档还需按兼容公式承接原投入和衣物槽。服务实际总攻击为 `1 + max(旧力量等级+旧武器槽等级, 2×当前强化等级) + 旧衣物槽等级 + 当前武器/衣物可生效攻击`。

验收要覆盖双资源同时扣除、门槛、旧档实际增量、保存失败回滚，以及下一局读取新攻击。本轮核对的是规则与配置，未把清单标为执行通过。

## 3. 皮肤系统

皮肤库承接收集、外观选择与现行穿戴属性。当前展示十五套，每套由四个部位构成，界面对玩家提供整套操作。

| 检查项 | 现行规格 |
| --- | --- |
| 怎么触发 | 点击皮肤卡试穿；点击“穿戴”提交；可点击“一键穿最强”；未拥有时查看获得途径 |
| 什么条件 | 试穿只改展示；正式穿戴要求该套四件均满足可穿条件，且没有未结束挑战 |
| 如何记录 | 选中卡与试穿角色是页面状态；正式穿戴写四个部位 ID；持有/外观权限保存在账号归属记录 |
| 结果与反馈 | 试穿立即预览但不改账号；穿戴保存成功后刷新实际角色、穿戴中标识和可生效属性 |
| 特殊情况 | 不把选中、已拥有、可穿戴和穿戴中混为一态；一键穿最强只在可穿整套中按实际攻击比较，同攻击优先当前穿戴；挑战中给出不能更换的提示 |
| 保存数据 | 正式整套更换与落盘作为一次事务；失败恢复全部四个部位，不能只换一半；浏览卡片不写穿戴存档 |
| 配置 | `campaign.json.equipments` 的套装 ID、部位、品阶、通关门槛、攻击/金币收益及 legacy 标记；四件归属和外观授权由现行服务判定 |

当前十五套覆盖 D/C/B/A/S 五档。默认见习巡夜人，其他套装按通关和现行权益取得；星海游侠关联武装整备，赤焰龙骑关联同行证。付费提前获得外观不等于立即取得全部高阶属性：未到原通关门槛时，属性不高于同部位当前可达的免费装备上限。

当前没有接入“解锁一套即叠加拥有攻击”的新方案；不能把界面“已解锁数量”理解成已实现拥有加成。皮肤碎片和星级也尚不属于当前存档。旧部位金币收益仍有服务，不写成已经按 v2.1 移除。

验收重点：未拥有试穿不污染账号；四部位一起提交；提前外观的有效属性；部分同行证部件尚未集齐；同攻击的一键穿戴；保存失败后角色与账号一致。

## 4. 永久技能培养与局内应用

| 展示项 | 当前局外功能 | 当前局内功能 |
| --- | --- | --- |
| 屏息 | 说明开局自带及局内成长 | 点击恢复耐力与冻结敌方；局内词条成长 |
| 瞄准 | 说明长按锁敌及局内成长 | 提高锁速、并行或额外瞄准；不是主动技能按钮 |
| 爆破 | 已见过且达到开放条件后可永久升级 | 主动范围爆炸，本局需按学习/开放规则取得 |
| 穿透 | 已见过且达到开放条件后可永久升级 | 主动激光；与永久伤害和本局词条结合 |
| 导弹 | 达到开放条件且已见过后可永久升级 | 主动导弹；按章节逐步开放 |
| 冲击波 | 说明效果及局内成长 | 主动推开、清弹；按章节开放 |

| 检查项 | 永久升级的现行规格 |
| --- | --- |
| 怎么触发 | 备战技能卡 → 详情 → 升级 |
| 什么条件 | 技能已开放且已在局内获得过；无未结束挑战；未到当前进度上限；金币及技能材料足够 |
| 如何记录 | 永久等级、已见技能、专属/通用材料各自保存；本局技能等级与词条不回写成永久等级 |
| 结果与反馈 | 消耗金币和材料，永久等级 +1；显示真实前后伤害、当前等级、材料余额和成功反馈 |
| 特殊情况 | 先用专属材料，差额用通用材料；未见过、未开放、阶段上限、总上限与资源不足分别提示；新模式护盾永久升级封闭，旧投资保留 |
| 保存数据 | 扣款、扣材料、升级一起保存；失败整体恢复；新出击读取永久伤害快照，续玩保持原快照 |
| 配置 | `maxDamageSkillLevel`、`skillCapsByCleared`、金币与材料成本公式；技能开放还由 `SkillAvailability` 和本局快照控制 |

当前三项伤害技能总上限为 20，阶段上限还受通关数表限制。等级 L 的升级金币为 `100 + 100L + 15L²`，材料为 `5 + 2L`。永久基础伤害输入为 `总攻击 + 2×永久等级`，实际技能倍率另见[战斗规格](../docs/noon-combat.html)。不能将页面的永久输入值直接当成每束激光或每枚导弹最终伤害。

现行技能页能显示材料，不代表所有原材料获取入口都仍开放。首章模式每日不再发通用技能材料，旧箱/材料直购入口收起，已有余额和其余现行奖励继续使用。后续应复查永久升级重新开放后，新玩家材料路径是否足够清楚；本稿记录依赖，不擅自补发奖励或打开旧入口。

## 5. 商城与商品权益

当前商城包含每日补给、现有礼包/同行证入口、两档灵晶补给、金币兑换与更多补给。首章成长模式隐藏旧技能宝箱及材料直购；当前没有新皮肤箱和技能箱。

| 商品/操作 | 当前配置或行为 |
| --- | --- |
| 巡夜见面礼 | 一次性：800 金币、150 灵晶、6 强化石 |
| 小/中灵晶商品 | 80 / 500 灵晶，可重复购买 |
| 武装整备 | 一次性：星海游侠 A03 四件外观权益、400 灵晶；已拥有部件按现行重复转化处理 |
| 巡夜同行证 | 购买解锁二十级进阶轨道，按等级领取；不是立刻发放全部奖励，也不是月订阅 |
| 金币兑换 | 20 灵晶换 200 金币，仍需通过资格和保存检查 |
| 每日补给 | 读取当前进度与领取历史；与七日签到分别记录，不合并成同一个领取状态 |

配置中的美元价格是开发示例。对外材料不把示例价格当正式商店定价，也不把开发模拟购买当真实支付成功。

| 检查项 | 现行购买与履约 |
| --- | --- |
| 怎么触发 | 商品卡 → 明细/购买确认 → 商店回调或开发模拟路径 |
| 什么条件 | 商品存在、可售、无冲突的购买/待履约流程；一次性商品未买；资源商品仍有用途；正式价格与商店就绪信息有效 |
| 如何记录 | 商品 ID、订单 ID、已购买权益、到账资源和待保存履约状态；订单去重与一次性商品去重分别检查 |
| 结果与反馈 | 收到可信购买结果后应用奖励，保存成功后再确认履约并显示到账；取消/失败不显示购买成功 |
| 特殊情况 | 重复回调不重复发奖；一次性已购不可再买；商店未就绪/价格缺失为不可售；保存失败保留待履约重试，不要求再付一次钱 |
| 保存数据 | 资源与订单记录一起落盘；落盘失败撤回未保存奖励，阻止其提前被花掉；保存成功后才向商店确认完成 |
| 配置 | `campaign.json.products`、兑换与每日字段；商品权益特殊规则由 Commerce/Pass 服务管理，商店网关负责正式购买结果 |

本稿不证明发行 SDK、收据验证后台或真实商店已完整接通。对应状态继续看发行交接。

## 6. 后续设计与已知问题

成长与商城 v2.1已有明确方向：五十级强化、皮肤碎片/升星/拥有加成、技能箱与皮肤箱、广告和新的资源来源。当前四级强化、十五套整套展示和永久技能入口是可核对的实装阶段，不能因页面已做好就宣布新经济层全部完成。

需要后续评审的事项：

- 当前四级强化与后续星级长期成长之间的过渡，沿 v2.1 任务卡推进，不能在策划补录中暗改敌人或收益。
- 永久技能入口已恢复，材料可得性与来源指引需按新玩家路线核对。
- 统一页面里的“章/星”用语；正文按玩家可识别的正式星级与章节关系解释，不能直接照搬内部零起算索引或旧文案。
- 真人复玩、付费意愿、经济压力与广告收益尚缺对应验证，不能从参数推算宣称已达到目标。

## 7. 实现依据与验证范围

- 备战页面：`BlueUpgrade`、`BluePreparationSkills`、`UpgradePreparationPower`。
- 皮肤页面：`WardrobeSkins`、`BlueWardrobe`、`WearWardrobeSkin`；整套服务：`OwnsSet`、`EquipSet`。
- 成长与账号：`Attack`、`TrainSlot`、`UpgradeSkill`、`Start`、`Settle`、`GrantVerifiedPurchase`；技能开放。
- 商城与技能弹窗：`BlueShop`、`BlueSkillDialog`；外观与商品权益。
- 账号事务：`TryAccountTransaction`；购买履约：`ProductDialog`、`Purchase`、`TryDeliverPurchase`。
- 当前配置与备战既有验证报告。旧验证报告仅用于理解已测范围，不当作本轮执行结果。
