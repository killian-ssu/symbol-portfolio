# 玩家测试方案

状态为待执行。现有独立试玩用于回答局内玩法问题，正式 Unity 首星用于回答完整玩家路径。已有受控输入和技术检查可以筛除运行问题，玩家行为和主观感受另行采集。

## 测试目标与范围

| 试验 | 样本与场景 | 本次唯一要判断的事 |
| --- | --- | --- |
| A 首星路径，优先执行 | 建议先约 5 位没玩过 Noon 的竖屏动作或轻肉鸽玩家，使用同一 Unity 构建，各用新档，自然游玩首星至第二次出击或主动结束 | 无人提示时，能否学会释放并看懂结算后的去向 |
| B 破绽时机，定位 A 的问题时执行 | 独立单关固定敌群、档位、资源和设备，先试当前实现。确需对照时只替换一种破绽提示，使用两组未见过关卡的玩家，或用两个等价局面交叉顺序并标记学习影响 | 提示能否改变松手时机 |
| C Boss 反制，另开一轮 | 成型配装直达 Boss 练习，和自然到达的完整局分开观察 | 能否看出反制对象、抓住窗口并理解力竭反馈 |

首轮 5 人用于查重复障碍。需要估算表现分布或判断渠道差异时另定样本和设计。使用手机时记录机型和系统，桌面操作和实体触屏各自标明。

## 测试准备

- 招募时问「过去一个月玩过哪些竖屏动作或轻肉鸽？」「之前玩过或看过《子时已到》吗？」先按经历选样本，已经熟悉 Noon 的人另记。
- 主持人把同一构建 ID、测试入口、语言、设备与新档检查记在表首。若中途更新构建，后续记录单独编号。
- 录屏前说明「这次是测试游戏，会记录操作和你的反馈，用编号汇总。可以选择只做笔记，或者随时停止。」记录同意范围后再开始。

## 测试执行流程

1. 试玩前登记包标识、版本、设备、语言、是否首次接触、是否玩过同类。征得同意再录屏，用匿名编号归档。
2. 给出任务「像平时一样玩，玩到你想停的位置」。让玩家自己发现玩法。第一次无助卡住时先记录当时画面与动作，需要提示时记录提示原话及之后的表现。
3. 记录第一次主动松手、第一次主动击破、第一次点燃超载、失败或胜利的退出位置。教程要求的动作与玩家脱离提示后自发重复的动作分别记。
4. 结算后给玩家自然选择。若进入强化，记录他看到的消耗和收益，是否愿意再出击，是否在下一星试到了强化。主动复玩和主持人要求复测分开记。
5. 结束后回看两个片段，问「刚才为什么松手？」「你觉得结算拿到了什么，下一步想做什么？」先听描述，再用术语追问。结束时保留一句最愿意再玩的理由或停止理由。

## 评估指标与判断标准

以下是本方案的工作阈值，实际招募前可调整。统计时写清分母，例如「4/5 无提示完成松手」「2/3 到达胜利结算的玩家找到强化」。缺少触达的项目继续收集。

- **操作理解**：建议以至少 4/5 无口头提示完成长按锁定并松手为继续条件。若至少两人反复点按或一直按住，回看锁定完成和松手前的提示。
- **窗口理解**：至少收集两段脱离教学后的主动击破或提前松手，能从动作和事后复述互相印证。总在耐力耗尽时松手，进入试验 B 定位。
- **成长理解**：记录到达胜利结算者是否理解资源已到账，能否指出强化的成本和收益。两人卡在同一个跳转或同一字段，先改界面再用新玩家复测。
- **复玩**：记录实际点第二次出击的人数和停止理由，用于定位下一轮要改什么。胜利、击破数或脚本耗时仅作为解释当局行为的上下文。
