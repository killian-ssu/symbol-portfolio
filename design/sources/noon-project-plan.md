## 执行流程

- 每轮开始记录目标版本、要解决的玩家问题、预计耗时、依赖和可验收产物。美术先用一个组件做短对照，玩法先用一个可玩片段，局外先跑通一张任务卡。日期随实际开始时间落到对应任务卡。
- 到约定检查点，先看代表结果是否成立。超出时间预算时，优先延后候选纹理、非主链路弹窗或新增商品。保留真实存档、支付、输入、到账与关键教学的验收。
- Claude 审阅框架、规格和任务卡。Codex 负责取证、独立样件、接入与回归。影响正式玩法方向、画风或首测范围的决定由 Symbol 确认，独立试验的参数可先使用可逆默认值。
- 决定写回对应维护文档与任务卡。局外见决策记录，美术样件见规范附录。验证结果随对应交付记录保存。

## 项目风险与应对

| 风险 | 何时能看出来 | 处理 |
| --- | --- | --- |
| 教程能走通，玩家仍只在耐力耗尽时松手 | 无口头提示的首星试玩 | 看行为与玩家复述，先定位提示、威胁或窗口，再只调一个变量 |
| 静态生成反复加细节，分层和对位返工 | 第一张代表页和普通／按下／禁用三态 | 先定结构与简单形状，从既有分件选一个底板做运行对照 |
| 多块底板同时动，文字和反馈变难读 | 样件扩到整页，尤其短屏和弹窗叠加时 | 记录同时运动范围、读数和渲染开销，根据同页观察决定扩展量 |
| 新成长和在途旧档互相影响 | 新档、历史成长档、在途快照对照 | 按规则版本核对结算、迁移、重复领取和恢复 |
| 商店履约验证受发行资料阻塞 | 完整 SDK 或真实商店服务不可用 | 记录阻塞资料，继续完成可独立验收的首段玩法、素材或界面 |
