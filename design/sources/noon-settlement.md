# 结算与复活设计

2026-11-13 · [整体设计](../docs/noon-system-overview.html) · [关卡节奏](../docs/noon-levels.html) · [局外成长](../docs/noon-progression.html)。按当前正式 Unity 源码与配置整理；仅核对规则和调用关系，本轮未运行游戏、操作真实账号或验证支付。

## 1. 胜败判定与结算时点

**胜利会结算入账；死亡先保存失败状态并允许决定是否复活，退出这一局才领取失败收益。** 复活不是新开局，不再次收出击体力；也不先领一次失败收益再继续领第二次。

| 事件 | 当前处理 | 玩家接下来做什么 |
| --- | --- | --- |
| 完成最后一个房间 | 保存胜利检查点，留出胜利表现时间，执行结算；保存成功后显示“奖励已入账” | 去强化、下一关/最终星再次挑战，或回主页 |
| 生命归零，未用过复活 | 保存失败检查点，等失败表现完成后显示统一失败页；奖励只是预览 | 花 40 灵晶复活，或回主页领取并结束 |
| 已复活后再死 | 保留失败状态，不能再次复活 | 回主页领取当前可带回收益 |
| 主动结束挑战 | 标记放弃，直接按失败收益结算并返回主页 | 从局外再准备；不绕回复活弹窗 |
| 暂停/切后台 | 保存当前挑战，未结算 | 恢复同一局；已锁目标的处理沿用用户已确认的规则 |
| 重进后恢复终局检查点 | 回到对应胜利/失败处理 | 不重开、不重复扣出击费、不重复发奖 |

胜利页当前若能做首章强化，主动作可为“去强化”；不满足时给下一关/再次挑战。失败页的“本局可带回”使用账号副本计算预览，不修改真实余额；“回到主页时领取，复活继续累积”对应实际入账时点。

## 2. 奖励构成与计算规则

下表的金币项相加得到最终金币。各星金额读取 `campaign.json.chapters`，不使用统一虚构的每关奖励。

| 收益 | 条件与算法 | 去向 |
| --- | --- | --- |
| 收集金币 | `min(本局收集量, 该星收集上限) × 单位换算 × 金币百分比 / 100`，整数截断 | 金币钱包 |
| 房间奖励 | 已完成普通房间数 × 每个房间的金币奖励；Boss 房不再计一次普通房间奖 | 金币钱包 |
| 通关奖励 | 完成全部房间才给 `clearCoins` | 金币钱包 |
| 首通奖励 | 该星第一次胜利给 `firstCoins` 与 `firstGems` | 金币与灵晶钱包 |
| 里程碑 | 每五星的首次通关，在尚未领取时给该星里程碑金币 | 金币钱包；同时标记已领 |
| 首次回收补助 | 账号首次结算且至少完成一个房间时额外给 40 金币；胜败均可，一次性 | 金币钱包；保存一次性记录 |
| 强化石 | 当前四级成长模式，首四星首次通关分别 1、2、2、3 个 | 强化库存 |
| 技能材料 | 符合条件的首通给 3 个通用材料；当前首五星彩用首章装备快照，不给这项；全部技能满级也不发 | 通用技能材料库存 |
| 头饰/鞋子金币加成 | 按本局保存的加成，对收集、房间、通关三项合计计算；不放大首通、里程碑和首次回收补助，最终星复刷另有规则 | 金币钱包 |
| 同行证经验 | 每完成一个房间 10 经验，首通再加 20，受总经验上限约束 | 同行证等级进度；轨道奖励仍需领取 |
| 通关外观 | 达到免费装备的通关门槛时将相应部件加入拥有记录 | 皮肤库整套可穿判定；不自动改穿戴 |

第一星新局只有三个房间；源码会把原七个房间定义少掉的四份房间金币补进首通金币，保留这一段预算。首通材料、经验与强化资格仍按真实结果处理。

**首星算例。** 假设新档首次胜利，收集计数为 39，无额外金币加成，尚未领首次回收补助，金币功能正常：收集金币 `floor(39 × 60%) = 23`，三个房间奖励 15，通关 50，首通 `50 + (7−3) × 5 = 70`，首次回收 40，共 **198 金币**；另有 **10 灵晶、1 强化石、50 同行证经验**。这是公式算例，不是本轮实机产出记录。

失败结算保留已经收集的金币及已完成普通房间奖励，可触发首次回收补助，也计已完成房间的同行证经验；不给本次未达成的通关、首通与里程碑奖。不把失败时剩余卡片折成永久技能或材料。

### 最终星重复挑战与成长上限

五十星全通后，最终星复刷的基础金币按普通完整收益比例缩放到配置预算 2000；未打完按实际获得比例计算，舍入余量统一归入一项，不重复加首通奖励。技能尚未全满时，每个服务日的前 3 次复刷胜利各给 8 个通用技能材料；服务日使用 UTC 日期。首次打通第五十星不消耗这 3 次复刷额度。

代码里的金币停止条件仍引用旧完整成长判断，不能把“当前四级强化已经满级”直接解释为“不再获得金币”。旧补给金币加成有兼容路径，但当前首章成长模式新开局不消费旧补给；不能把兼容项写成新玩家必经系统。

## 3. 复活规则

| 检查项 | 当前规则 |
| --- | --- |
| 操作 | 在失败页点击标明 40 灵晶的复活按钮 |
| 条件 | 仍有本局、模型为失败、本局未用过复活、余额足够；保存失败等待中不能重复提交 |
| 记录 | 同一挑战 ID 标记复活已使用；扣除灵晶，生成复活后的检查点 |
| 结果 | 恢复 2 心、耐力补满，短暂 2 秒无敌；清理旧锁定、待射队列和敌弹，把贴身普通敌人推回安全状态；保留本局已获能力、进度及收益 |
| 超载与技能 | 按复活保存规则保留热量和剩余冷却；不把复活当免费冷却刷新。危险中的临时攻击/表现状态清理 |
| 反馈 | 保存成功后关失败页，恢复同一战斗；灵晶不足时提示或进入现有补给入口，不直接复活 |
| 失败处理 | 先保存扣款、已用次数和复活检查点，再让战斗恢复。保存失败则恢复余额和未用状态，留在失败状态供重试 |
| 配置 | 费用为 `campaign.json.reviveCost`；每局一次、恢复心数、无敌及清场细则在服务与战斗模型中定义 |

## 4. 数据保存与系统关联

结算先验证挑战 ID、检查点、完成房间数量与终局状态，读取本局快照；成功时把奖励、星级进度、同行证经验、已见技能、免费装备归属和已结算标记一起写入账号，并清除进行中的挑战。`run:挑战ID` 防止同一局重复结算。

账号修改与保存有回退：如果结算落盘失败，恢复修改前账号，显示“奖励暂未到账，重试保存”；成功落盘后才把“已到账”交给玩家。不能仅因为内存余额变了就宣称保存成功。复活也独立保证扣款和检查点一致。

| 连接的系统 | 结算交给它什么 | 下一次发生什么 |
| --- | --- | --- |
| 星级进度 | 首通/完成房间数量/尝试与失败记录 | 开放下一星、强化门槛与对应技能池 |
| 强化 | 金币、强化石、通关资格 | 玩家选择升级，新的攻击在下一次出击生效 |
| 永久技能 | 金币、符合条件的技能材料、已见技能记录 | 达到资格后可培养；不继承局内词条 |
| 皮肤库 | 免费部件的拥有资格 | 整套条件满足后可穿；通关领奖不强制换装 |
| 商城与同行证 | 资源余额、经验等级 | 商城是另一条资源/外观来源；同行证购买解锁轨道，结算经验推动等级，领取仍单独处理 |
| 下一次战斗 | 清除旧挑战，保留永久账号 | 新出击再检查体力并保存新的成长与规则快照 |

## 5. 已知问题与验收要求

一个已定位的文案偏差：胜利结果页仍有“第十星后选卡开放护盾”的旧提示，而正式新超载卡池已过滤护盾，后续开放的是冲击波。策划以真实卡池为准，将提示列为待修正，不把它当成新模式规则；本次没有修改游戏文案。

后续实测要覆盖：胜利自动入账；失败预览不入账；复活后再结算一次；第二次死亡不能复活；主动放弃；退出后恢复终局；首次回收补助和里程碑不重复；扣款/发奖保存失败回退；强化石与同行证经验落到正确入口；最终星跨 UTC 日期的奖励次数。本轮仅完成源码、配置与算例核对。
