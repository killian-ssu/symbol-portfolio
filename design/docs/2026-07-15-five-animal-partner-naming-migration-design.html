档案说明

这是 2026-09-19 从工程收录的文本，可能包含后来补写的注释。正文中的“当前”“已实现”保留原有语境，不代表本站试玩版已逐项复验。

日期：2026-07-15

状态：已确认 范围：世界观、稳定 ID、玩家可见命名、配置适配、代码与测试同步

1. 目标#

把当前 v0.4 工程迁移到“五兽商队远行笔记”设定，同时保持既有玩法、数值和视觉资源不变。

本次迁移后的玩家核心认知是：

玩家带领鹰、狼、龟、蜂、鼠组成的远行商队
→ 从伙伴手牌中打出伙伴牌
→ 把伙伴依次放入 5 个行动格
→ 伙伴与道具从左到右结算
→ 完成地点记录并带回货品

2. 不在本次范围内#

  • 不替换、生成或重绘图标与图片。
  • 不修改颜色、美术风格、SpriteFrame 或资源路径。
  • 不修改 Prefab 布局、节点绑定、动画时长、缩放、粒子和其他 Inspector 参数。
  • 不改变牌型、探索度、角色成长、道具、工具、特别状况、奖励或关卡的数值与规则。
  • 不给旧行动 ID 和旧地点 ID 增加运行时兼容层。
  • 不实现货仓、行情、好友、路线或事件等当前首期范围以外的系统。

旧图标在开发期间继续作为占位。图标与新伙伴含义不一致不属于本次迁移缺陷，后续由用户替换并重新核对绑定顺序。

3. 真相源与文档结构#

3.1 历史快照#

docs/v04-rightward-chain/ 保持原样，继续记录 2026-07-11 的 v0.4 交接状态。迁移扫描和验收不得要求该目录清除旧名称或旧 ID。

3.2 当前真相源#

新建 docs/v05-five-animal-caravan/，作为当前策划真相源，包含以下六份文档：

  • AI_READ_FIRST.md
  • worldview-naming-ai-handoff.md
  • yuanxing-shangren-current-gdd.md
  • action-progression-boss-system.md
  • relic-tool-catalog.md
  • balance-tables.md

内容以 [本机工作目录] 下 2026-07-15 文档和数据为基础，并应用本设计中由用户追加确认的两项覆盖规则：

  1. 五类稳定 ID 使用动物 ID，而不是 scout / clear_path / supply / gather / treasure。
  2. 玩家可见对象统一称为“伙伴牌”，只显示动物名称，不显示“侦察、开路、补给、采集、寻宝”。

根目录 AGENTS.md 和 docs/ai/ 更新为指向 v0.5 真相源。原先“四份 7 月 11 日 JSON 必须原样保持”的约束改为历史说明，不再约束当前运行配置。

4.1 最终定义#

玩家可见牌面只显示“鹰、狼、龟、蜂、鼠”。不显示行动副标题，不要求玩家记忆角色姓名。

4.2 内部结构名#

为降低无效改动和回归风险，以下纯开发结构继续保留：

  • ActionType
  • actionHand
  • ActionProgressManager
  • ORIGINAL_ACTION
  • RETRIGGER_ACTION
  • playerType / resolvedType
  • action_progression.json

这些名称描述结算协议，不属于玩家可见世界观。其取值改为五个动物稳定 ID。

5. 地点与特别状况#

顺序v0.4 地点当前地点当前稳定 ID
1雾林雾叶林mistleaf_woods
2河湾回声湾echo_bay
3荒坡风草坡windgrass_slope
4金砂谷晶砂谷crystal_sand_valley

玩家界面使用“地点终页”和“特别状况”，不显示“Boss 关”或“Boss 规则”。内部 Boss 类型、管理器和字段可以继续保留。

20 条特别状况采用 2026-07-15 数据中的名称、文本、稳定 ID、地点归属和效果枚举。应对类型按下列方式替换：

scout     → eagle
clear_path → wolf
supply    → turtle
gather    → bee
treasure  → mouse

应对进度只显示伙伴，例如“派鹰 2/4”。不显示“鹰·侦察”等副标题。

6. 玩家可见术语#

6.1 固定术语#

旧表达当前表达

五类行动累计五名伙伴成长
此区域行动此行动格的伙伴
右侧行动右侧行动格的伙伴
所有行动所有伙伴
行动再次触发伙伴再次行动

Boss 规则特别状况

以下术语保持不变：

  • 行动格
  • 道具
  • 工具牌
  • 牌型
  • 探索度
  • 刷新
  • 伙伴的结算分数

6.2 文案样式#

配置和界面使用完整、无歧义的对象表达：

此行动格的伙伴+5。
右侧行动格的伙伴再次行动1次。
所有伙伴+5。
1张伙伴牌变为任意伙伴。
重抽1张伙伴手牌，可选3张。
本轮所有伙伴再次行动1次。

不使用“侦察、开路、补给、采集、寻宝”作为伙伴副标题，也不使用“角色牌”或“所有角色”作为同义词，以免同一界面出现两套术语。

7. 配置迁移#

7.1 action_cards.json#

  • 把五类 ID 和名称改为动物稳定 ID 与动物名称。
  • 每类数量仍为 5，基础探索度仍为 10。
  • 现有 color 和 icon 字段值不主动调整。
  • 配置顺序不得作为玩法判断依据；玩家显示顺序由明确的伙伴顺序常量控制。

7.2 action_progression.json#

  • 五类 ID 改为动物稳定 ID。
  • 名称只使用动物名称。
  • 货品标签沿用 v0.5 五兽版的对应关系。
  • 阈值、每级成长和权重系数保持不变。

7.3 boss_rules.json#

  • 使用四个当前地点 ID 和名称。
  • 使用 2026-07-15 的 20 条特别状况稳定 ID、名称和玩家文本。
  • 计数对象改为动物稳定 ID。
  • effect 的新版枚举由现有 Boss 解释器等价支持。
  • 所有系数、解除数量和额外货品候选规则保持不变。

7.4 relics.json 与 tools.json#

  • 道具和工具稳定 ID 保持不变。
  • 名称采用 2026-07-15 简约器物命名。
  • player_text 按“伙伴牌 / 伙伴 / 再次行动”术语重写。
  • effect、condition、growth、目标、数值和结算时机保持不变。
  • old_mold 仍生成 copy_paper，玩家看到“获得1张铜镜”。
  • spare_box 仍生成 search_hook，玩家看到“获得1张网兜”。

7.5 levels.json 与其他配置#

  • 16 关的地点 ID 和场景名切换到当前四地点。
  • 每关目标、轮数、刷新次数和终页位置不变。
  • patterns.json 的牌型与倍率不变。
  • rewards.json 的奖励结构、权重和工具稳定 ID 不变；玩家可见工具名称从工具配置读取。

8. 代码适配#

8.1 类型与固定顺序#

  • ActionType 联合类型改为五个动物稳定 ID。
  • Core、兼容门面和 UI 的固定集合全部使用同一组 ID。
  • 伙伴显示顺序固定为鹰、狼、龟、蜂、鼠。
  • HUD 降级名称只保留五个动物名称。
  • Inspector 中的图标数组 tooltip 更新为新伙伴顺序，但不修改实际绑定。

8.2 配置校验#

校验器必须：

  • 要求五个动物稳定 ID 恰好各出现一次。
  • 要求四个当前地点各有 4 关和 5 条特别状况。
  • 接受并校验 v0.5 特别状况效果枚举。
  • 继续验证 40 件道具、10 张工具及全部稳定 ID。
  • 对未知旧 ID 给出精确配置路径错误。

8.3 特别状况解释器#

新版效果枚举映射到现有等价逻辑，不另写第二套玩法。重命名只发生在配置协议入口，内部结算步骤和随机数调用顺序保持不变。

8.4 UI 文案#

  • HUD 采用动物名称和“伙伴成长”。
  • 特别状况标题明确显示“特别状况：名称”。
  • 应对组件显示“派{伙伴} count/required”。
  • 结算、奖励和局末界面清除当前实现范围内的“行动牌”和玩家可见 Boss 表达。
  • UI 不新增目标判断、牌型判断或结算逻辑。

9. 数据流#

v0.5 JSON
→ V04ConfigValidator 校验动物 ID、地点 ID 与稳定配置
→ V04GameSession 继续按 ActionType 协议结算
→ GameSession 兼容门面输出当前状态
→ GameMainViewComp / HUD 读取配置名称
→ 玩家只看到伙伴牌、动物名称、地点终页和特别状况

UI 不建立旧 ID 到新 ID 的映射。迁移关系只用于一次性修改配置、代码和测试。

10. 兼容性与错误处理#

  • 旧行动 ID、v0.5 初稿行动 ID 和旧地点 ID 在当前运行配置中均视为非法。
  • 当前项目没有正式存档迁移，本次不保留旧运行状态兼容。
  • 配置加载失败时沿用现有“精确字段路径 + 阻止开局”的策略。
  • v0.4 历史文档和归档内容允许保留旧词，不参与运行时校验。

11. 验证策略#

11.1 配置与语义验证#

  • 五个伙伴 ID 恰好为 eagle / wolf / turtle / bee / mouse。
  • 四个地点 ID 恰好为当前定义。
  • 40 件道具和 10 张工具的稳定 ID 集合不变。
  • 道具和工具的效果、条件、成长、数值与目标未被命名迁移改变。
  • 20 条特别状况的目标系数、解除数量和效果数值与 v0.5 数据一致。
  • 当前配置、Core、UI 降级文案和测试中不残留旧行动 ID、初稿行动 ID 和旧地点 ID。
  • v0.5 交接文档允许在明确标注的迁移对照表中保留旧 ID；当前规则正文不得继续把旧 ID 当作有效值。

11.2 行为验证#

继续覆盖：

  • 每 10 张同一伙伴牌，本局对应伙伴永久 +2，并在当轮结算前生效。
  • 工具改变伙伴后按改变后的伙伴累计。
  • 特别状况强制改变结算类型不改写玩家累计。
  • 伙伴再次行动和道具再次触发不进入累计。
  • 五格右向连锁、牌型、奖励、摘要和 16 关推进结果不变。

12. 验收标准#

迁移完成必须同时满足：

  1. 玩家只看到鹰、狼、龟、蜂、鼠五张伙伴牌。
  2. 玩家可见文本统一使用“伙伴牌 / 伙伴手牌 / 所有伙伴”。
  3. 当前运行配置只使用动物稳定 ID 和当前地点 ID。
  4. 道具、工具、特别状况和关卡的玩法与数值没有变化。
  5. v0.4 历史快照保持原样，v0.5 真相源完整可读。
  6. 美术资源和 Prefab 没有被本次迁移修改。
  7. 全部自动验证通过。
