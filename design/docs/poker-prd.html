扑克牌格子三消·构筑爆分型（PRD）

用扑克花色与点数构成格子三消，定义短局构筑的最初产品目标。

档案说明

这是 2026-09-19 从工程收录的文本，可能包含后来补写的注释。正文中的“当前”“已实现”保留原有语境，不代表本站试玩版已逐项复验。

1. 背景与目标#

我们基于 SUIT‑UP 的“5×3格子 + 3手牌 + 下落变形 + 连锁消除”框架，做一个更偏 Balatro 的“构筑爆分型”小游戏：

  • 保留：上手即懂的扑克牌语义（4花色×点数）、空间紧张与连锁爽感
  • 增强：通关三选一构筑，让玩家明显感到“越玩越强”“体系成型分数起飞”
  • 约束：保持小游戏体量，不引入经济系统与复杂长线养成

2. 用户画像（假设）#

  • 喜欢轻度策略/解题/消除的玩家
  • 追求“连锁爽、分数跳档、再来一局”的短局体验
  • 不想学习复杂牌型/复杂数值系统的玩家

3. 核心卖点（对外一句话）#

在 5×3 的扑克牌棋盘上做连锁三消，用三选一构筑把连锁倍率越滚越大，打出离谱高分通关 16 关。

4. MVP范围#

4.1 必做（MVP）#

  • 16关（含4个Boss关）
  • 5×3盘面 + 顶部缓冲行
  • 手牌：基础3张扑克牌；出牌后补1张
  • 消除：相邻三连（同花/同点/顺子），支持更长连线；支持 A↔K 循环顺子
  • 下落：整行清空→上方行整体下移（行重力）
  • 计分：按“消除张数N + 连锁段数系数”计分
  • 胜负：目标分 + 回合数；盘面满且无处放牌也失败
  • 通关奖励：每关三选一；Boss关额外三选一
  • 道具槽位3；工具容量默认3（可升至4）
  • 工具牌池5种（删/改色/重抽/回收/清行）
  • 工具牌独立发放：每关保底一次 + 概率额外（详见GDD）

4.2 暂不做（MVP不包含）#

  • 货币/商店
  • Jobs 倒计时任务系统
  • 十字/L/T等形状奖励判定
  • 牌库预览/定向抽牌/删牌等复杂牌库操控
  • 局外成长（永久解锁/天赋树）

5. 体验指标（验收标准）#

5.1 可玩性#

  • 新手无需教程也能在 30 秒内完成一次有效消除与下落连锁
  • 玩家能在前3关中至少体验到一次“≥3段连锁”的爽感

5.2 构筑感#

  • 通关三选一的选择会导致“明显不同的打法倾向”（至少：连锁派 vs 稳健派）
  • 道具 槽位受限（3槽）仍能做出可辨识build

5.3 难度与失败归因#

  • 失败主要来自：回合不足 / 盘面塞满（可归因），而不是“看不懂规则”
  • Boss关通过“规则约束”制造压力（而不是只抬目标分）

6. 内容配置（MVP规模建议）#

为保证小游戏体量与可迭代性：

  • 道具：10张（先做玩家一眼懂的触发器）
  • 规则升级：3个（手牌上限/回合数/工具容量）
  • 工具牌：5种
  • 关卡配置：16条（目标分、回合数、Boss规则）

7. 技术与实现约束（对开发）#

  • 引擎：Cocos Creator 3.x
  • 框架：Oops Framework（建议以官方模板 oops-game-kit 作为项目基底）
    • Oops Framework 概览与文档入口：https://github.com/dgflash/oops-framework/wiki/Oops-Framework
  • 数据驱动：关卡、道具、工具牌、升级尽量使用 JSON 配置（便于 Trae Solo 快速迭代）

8. 风险与对策#

  • 风险：连锁倍率过高导致数值失控
    • 对策：连锁段数系数封顶；规则升级封顶；Boss关提供连锁抑制规则
  • 风险：工具牌发放过少导致体验过“硬”
    • 对策：每关保底一次工具牌发放 + 概率额外发放；工具牌进入手牌不占基础手牌上限
