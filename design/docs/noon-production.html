本页为项目开发与验证方案。计划、评审要求和待执行测试均不代表已完成验证。

从玩家体验切成一个能玩、能看或能验收的任务，先走通代表样例，再扩到同类页面或关卡。本规程适用于内部制作。现有系统排期走局外系统计划，页面与素材规格走 UI 制作 SOP和素材技术规格。

阶段与交付条件

阶段 最小产物 进入下一阶段的依据
立项与玩法 玩家动机、预期决策、失败信号、可重复试玩入口 Symbol 能试玩并判断核心行为有没有出现，待验证项写明下一次怎么测
页面分析 入口、主任务、内容优先级、触发与返回、空态和失败态 单凭流程能说清玩家看到什么、点什么、何时到账
低保真 灰阶线框，覆盖正常、受限、返回和代表短屏 Symbol 审阅，修订本批页面结构和信息
画风与代表页 Symbol 给画风参考与美术要求。制作方复用已有源稿和组件，给代表整页与状态样例 在实际显示尺寸确认气质、对比度、字重、可读性，决定复用和补制清单
分层与引擎对位 可编辑母稿、透明分件、组件清单和一个实机页面 原稿与 Unity 渲染同画幅对照，核对控件位置、适配与真实事件
动效与整合 一条完整动作的静态关键帧、短样片、接入版本和可复现步骤 真实成功／失败事件驱动，完成、取消、暂停、重开和快速重复操作均有明确结果
验收与交付 构建身份、分层检查证据、已知限制、接手入口 正确构建中的相关状态已复测。策划体验结论由实际试玩支持

已有画面先查源稿、实际接入和本次页面变化。能复用的组件按原登记沿用，缺的从页面分析导出补件。整页图用于审视视觉与构图，数据、文案、按钮和交互层继续独立。

职责分工

角色或工具 负责
Symbol 确定体验、规则取舍、页面结构、画风要求、代表效果和人工验收
主 AI 会话 查版本与基线，拆任务，标记依赖，整合规格、素材、代码和验证证据
策划与复核 AI 在既有局外系统计划中已有 Claude 写规格和任务卡、Codex 实现和验证的安排。每轮指定实际负责人和交接范围
图片生成与 Photoshop 生成候选、整理分层母稿、导出素材。记录实际来源、工具、模型和版本，付费批次按已定范围执行
资源工作台与引擎 工作台负责查找、修改入口、版本和替换关系。UI Toolkit 先做独立对位样件，正式页面接既有运行入口及数据。Cocos 单列导入、图集、热区及平台验证

多人或多 Agent 同时执行时，任务卡写明交接物和各自写入范围。同一个界面、配置或正式场景由一方负责合并。实际使用的工具按产出写入记录，研究过的方案和已接入工具分别标明。

任务说明模板

每个阶段只填本轮需要的字段。放进相应模块的现有任务卡和报告目录。

字段 填写方式 首轮示例
玩家问题 一句话，写具体动作 首通后能否找到强化，并看懂升级前后的攻击和实际成本
版本与证据 目标版本、页面状态、相关规则与实机基线 Unity 首章、首通第一章第一星后的结算和四级强化预览
范围与依赖 本轮产物、涉及的页面、需先完成的事情 结算与强化线框，包含成功、资源不足、未开放。画风在结构审阅后给出
分工与写入 决策人、执行人、文件或素材位置 Symbol 审阅结构，执行方编辑本流程目录的独立线框
通过条件 指明要看到的可复现结果 从结算进入强化，玩家能区分持有与消耗，操作后余额和攻击同时刷新
证据与状态 实际做了什么、验证方法、构建及后续事项 线框点击检查与截图。进入 Unity 后补中英文、短长屏、真实数据、触控与存档

设计发生冲突时，在规格所在位置记录日期、决定、理由、适用版本、替代旧项和实际验证状态。汇报时引用一处主文档，避免同一规则在策划稿、交互稿和报告里各自演变。

线框评审与美术需求模板

Symbol 审阅线框后，用这张卡交接一个代表页或组件。只填会影响本轮取舍的字段。

字段 要填的内容
审阅范围和决定 页面、状态、线框版本、通过项、待修项、评审人和日期
画风参考 图或片段来源、时间点、在游戏内看到的特征、希望借用的做法
形状与信息层级 主要轮廓、强调对象、文字对比、留白。注明需要避开的写实程度、装饰和遮挡。参照形状、配色与状态矩阵
复用与补件 工作台 ID 或可编辑原稿，缺件及用途。尺寸、锚点、九宫格等沿用 UI SOP 素材交付契约
动效与状态 哪个真实事件触发，普通、按下、禁用、成功及失败时显示什么。底纹、按钮动作和短特效各负责什么。参照动效分工
代表样件与验收 目标画幅、可操作样件、静态对照、通过和停止条件。每轮优先比较一个变化

例如「同一块强化底板，有纹理与无纹理」先固定形状、配色、字号和按钮动作，只观察纹理能否在实际尺寸下增加层次并保持文字可读。选定纹理后再测流速或对比度。 Claude 样件提纲

美术资产与动效交接

  • 设计到美术。输入含批准线框、关键画幅、页面热区、真实文案、画风参考、复用清单和不同状态。至少先试实际会拉伸的按钮、信息底板或卡片和一种弹窗。
  • 美术到程序。每件记录稳定 ID、原稿图层、输出尺寸、可见边界、锚点、层级、九宫格／等比／裁切规则、动态文字、资源路径、许可来源和替换关系。复用原 .meta 与资源 ID。工作台核对缩略图、数量、搜索、来源和可编辑入口。
  • 对位到动效。保留同一画幅的静态基准，先用独立样件验证分层与布局，再以正式引擎入口回归实际状态。样件通过时记录它使用的是演示还是真实数据。
  • 动效到运行。示例可选「强化成功」：事务成功后刷新数值，由 Animation 或 Tween 组织节点亮起和攻击变化，粒子补短促的奖励反馈，Shader 承担有需要的材质变化。记录触发、起止、层级、可打断点和跳过后的最终状态。保存失败回到可操作态，已有确认的收益只结算一次。工具组合留到动效专项。 已有动效拆解

验证从本轮变动出发。规则断言、引擎画面、真实输入、人工手感、手机硬件和发行服务各用对应证据。持续用同一构建身份检查入口与产物。发行相关回执放所属发布记录。
