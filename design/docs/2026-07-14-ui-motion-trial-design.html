把关键动效做成可比较、可调整的试验。

档案说明

这是 2026-09-19 从工程收录的文本，可能包含后来补写的注释。正文中的“当前”“已实现”保留原有语境，不代表本站试玩版已逐项复验。

日期：2026-07-14 状态：已确认试做范围，待实机调参

1. 目标#

先用最小一批真实界面验证手机端 UI 手感：

  • 主菜单“开始游戏”按钮。
  • 局内“刷新”按钮。
  • 5 个行动格在自动结算时的命中动效。

本轮不实现分数区弹跳、资源数值动画、全局时间暂停、鼠标悬停、粒子、镜头震动和新音效。先确认按钮与行动格的缩放曲线，再向分数表现扩展。

2. 设计原则#

  • 手机优先：以 TOUCH_START / TOUCH_END / TOUCH_CANCEL 为主，不依赖鼠标悬停。
  • 不改规则：动效只属于 UI 层，不改变刷新次数、行动格结算和分数。
  • 可打断：新一次按压或结算触发到来时，先停止该播放器自己创建的上一次动效，从已记录的基准状态重新播放。不停止其他系统作用在该节点上的 Tween。
  • 不累积误差：所有缩放都相对节点原始 scale 计算，不把当前缩放继续相乘。
  • 可逐步推广：按钮和行动格共用底层 Tween 播放与基准状态处理，但使用不同曲线预设。

3. 方案选择#

方案 A：分别写在三个现有页面中#

优点是代码量最小。缺点是参数、打断逻辑和基准缩放会重复，后续接入其他按钮容易出现手感不一致。

方案 B：通用播放器 + 按钮组件（采用）#

用一个轻量通用播放器实现曲线、基准状态和打断；用按钮组件负责触摸状态；行动格在结算序列中显式调用命中预设。

这个方案既能快速试手感，也能保留后续给分数、倍率、资源数值复用的入口。

方案 C：完整数据化动效资产#

把时长、幅度、曲线全部做成 Cocos 可编辑资产。扩展性最强，但在手感未定稿前会增加不必要的编辑器配置和维护成本，本轮不采用。

4. 按钮动效#

4.1 接入范围#

  • main_menu.prefab 中的 StartBtn。
  • game_main.prefab 中的 RefreshBtn。

两个按钮现在都有 Cocos Button 的 Scale transition。通用按压组件启用时，运行时关闭该节点自带的 transition，避免两套缩放叠加。不直接修改预制体序列化数据。

4.2 默认曲线#

  1. 按下：0.06s内到达 scaleX = 1.03、scaleY = 0.94，使用快速 Ease Out。
  2. 按住：保持压下状态，不额外循环。这本身就是长按反馈，避免让普通按钮看起来像存在特殊长按功能。
  3. 松开：0.10s 到 scaleX = 0.98、scaleY = 1.05，再用 0.14s backOut 回到基准缩放。
  4. 取消：0.12s sineOut 直接回到基准缩放，不播放过冲。

初始参数是试手感起点，实机后优先调整四项：按下时长、纵向压缩、回弹过冲、回弹时长。

4.3 点击行为#

  • 按钮原有 TOUCH_END / Button.clickEvents 不改，不把业务回调塞进动效组件。
  • 本轮不强制延迟进入游戏或刷新逻辑，保持触摸响应立即。
  • StartBtn 若因为页面立即销毁导致回弹不可见，实机证明后再为菜单转场单独增加最多 0.08s 的表现窗口，不先入侵页面跳转。

5. 行动格结算动效#

5.1 接入方式#

  • 5 个行动格全部启用。
  • 动效在 GameMainViewComp.playSettlementSequence() 的逐格结算循环里触发。
  • 格子提供一个明确的 playSettlementImpact(intensity) 入口，不把结算规则放入动效组件。
  • 动效对“格子内的卡牌展示根节点”播放，不改整个网格布局节点，避免影响命中区域和长按识别。

5.2 默认曲线#

  1. 砸下：0.055s 到 scaleX = 1.08、scaleY = 0.88，使用硬朗的 Ease Out。
  2. 局部卡肉：保持上述状态 0.05s。只延长当前结算表现序列，不改全局 timeScale。
  3. 反向拉伸：0.075s 到 scaleX = 0.95、scaleY = 1.10。
  4. 回弹：0.16s backOut 回到基准缩放。

现有的逐格音效和浮字保留。原本的通用左右抖动不再同时作用在卡牌节点上，避免缩放与抖动互相抢戏。

5.3 强度参数#

intensity 本轮默认为 1，范围限制在 0..2。它只放大相对基准 scale 的偏移量，不改变基准 scale：

  • 0：可用于关闭冲击，直接恢复基准状态。
  • 1：当前试手感的标准命中。
  • 2：后续连锁爆发的上限参考。

本轮 5 个格子均使用 1，不做逐格增强。等动画曲线确认后，再将随身物触发次数或连锁深度映射到该参数。

6. 数据流与打断规则#

按钮#

TOUCH_START -> 记录/恢复基准状态 -> 按下 Tween -> TOUCH_END 回弹

  • 新一次 TOUCH_START 会停止该节点上的旧动效。
  • 播放器保存并只停止自己的 Tween 实例，不调用 Tween.stopAllByTarget(node)。
  • TOUCH_CANCEL 恢复但不过冲。
  • 组件禁用或节点销毁时解绑事件，并恢复 Cocos Button 原 transition。

行动格#

SettlementResult.cardLines -> 现有逐格循环 -> 对应格子 impact -> 本格浮字/累加 -> 等待下一格

  • 每格冲击返回可等待的 Promise，但结算序列只等待到“卡肉点完成”，回弹可以和浮字重叠，防止整体结算过慢。
  • 如果节点在动画期间失效，Promise 必须正常结束，不能卡住结算。
  • 如果旧动画被新一次冲击打断，旧动画对应的 Promise 也必须正常结束。
  • 页面退出或新一轮刷新前，将节点恢复到基准状态。

7. 预计文件#

新增：

  • assets/script/game/common/ui-motion/UIMotion.ts：通用基准状态、停止和曲线播放器。
  • assets/script/game/common/ui-motion/PressFeedbackComp.ts：手机按压生命周期组件。
  • 对应的 Cocos .meta 文件。
  • scripts/test-ui-motion-contract.js：检查接线、参数约束和不侵入核心逻辑。

修改：

  • assets/script/game/initialize/view/MainMenuViewComp.ts：给 StartBtn 运行时接入按压组件。
  • assets/script/game/buildscore/ui/GameMainViewComp.ts：给 RefreshBtn 接入按压组件，在逐格结算中调用冲击。
  • assets/script/game/buildscore/ui/BoardViewComp.ts：对外提供行动格结算冲击入口。
  • assets/script/game/buildscore/ui/BoardCellStampComp.ts：在卡牌展示根节点上播放冲击预设。

本轮原则上不修改 .prefab，避免与当前已存在的大量未提交 UI 调整产生冲突。

8. 验收标准#

按钮#

  • 开始游戏和刷新按钮在手机触摸开始时立即压缩。
  • 按住不松时稳定保持，不循环抖动。
  • 松开后有可见过冲且最终精确回到原缩放。
  • 划出按钮或触摸取消时恢复原状，不触发业务行为。
  • 连续快点不会越点越大、越点越小或停在中间缩放。
  • 刷新成功/失败逻辑与音效保持现状。

行动格#

  • 自动结算时 5 个格子依次播放相同的砸下—停顿—拉伸—回弹。
  • 存在可感知的短停顿，但背景与其他 UI 不被全局冻结。
  • 动效不改变格子位置、命中区域、长按遗物详情和最终分数。
  • 一次结算完成后，5 个格子都精确回到各自原缩放。
  • 不因节点失效或中途退出导致结算永远等待。

9. 实机调参顺序#

  1. 先调按钮的纵向压缩和回弹时长。
  2. 再调行动格的砸下幅度和 0.05s 卡肉时长。
  3. 确认结算总节奏后，再接入“行动格短延迟爆分”。
  4. 最后接入分数区、倍率和资源数值的通用弹跳。
