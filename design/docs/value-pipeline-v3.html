版本：2026-08-01

状态：历史版本，已由 value-pipeline-design-v0.4.md 取代。运行时数值仍以 assets/resources/config/gameplay/ 为最高优先级。

1. 当前结论#

一轮只有一个持续变化的数值。它从 1 号位开始，依次经过 2—5 号位；每个位置完成全部行动后再向右传递一次，5 号位结束后的数值就是本轮得分。

这套机制不再使用牌型、伙伴固定分数、独立倍率区、道具向右触发或多个批次。五张牌本身就是向右结算语言，道具只修改初始价值、增加值、此处行动、此处结算或永久提升。

2. 玩家可见名词#

名词精确定义
初始价值本轮开始传递前显示的数值，基础为 10；出牌阶段即可看见
当前价值正在从 1 号位向 5 号位传递的唯一数值
增加值1 号位或异色伙伴每次行动增加的数值，基础为 10
行动伙伴在此处执行一次规则；额外行动会再次执行相同规则
此处这件道具当前放置的位置
同色伙伴当前伙伴与前一位颜色相同；每次行动使当前价值 ×2
异色伙伴当前伙伴与前一位颜色不同；每次行动使当前价值 +增加值
永久本次远行后续关卡都保留
永久数值提升道具或事件在本次远行中累计并保留的数值增加

卡面不能只写“相同时”“每 10 张牌”“每格永久+20”这类省略对象的短句。每条玩家文案至少说清：什么条件、影响什么对象、改变什么数值、持续多久。

3. 基础公式#

current_value = initial_value

for slot in 1...5:
  repeat action_count(slot) times:
    if slot == 1:
      current_value += increase_value
    else if partner(slot) 与 partner(slot - 1) 同色:
      current_value *= 2
    else:
      current_value += increase_value

round_score = current_value after slot 5

基础值：initial_value = 10、increase_value = 10、同色倍率固定为 2。单个位置最多 10 次行动。

排列运算本轮得分
AAAAA(10+10)×2×2×2×2320
ABCDE10+10+10+10+10+1060
ABBBC10+10+10→×2→×2→+10130

额外行动始终作用于同一个当前价值，不新建数值、不回传、不产生独立批次。

4. 道具设计约束#

一件普通或稀有道具可以提供简单而明显的偏好，但不能自动替玩家完成多个未来位置的排列。判断标准不是“文本是否短”，而是玩家获得该道具后，之后每轮是否仍有至少两种有意义的出牌形状。

允许的单件作用：

  • 修改初始价值或增加值；
  • 修改此处的行动数；
  • 在此处行动后或位置结束后增加当前价值；
  • 记录伙伴、行动、工具或过关次数，形成永久提升；
  • 生成一张工具，让玩家主动改变一张牌或一个位置。

默认不允许：

  • 自动改写两张或以上尚未打出的伙伴；
  • 一件道具直接固定后三位颜色；
  • 不经玩家选择就生成一个完整五连；
  • 为了解释道具而重新引入第二批数值或反向传递。

风筝修订#

旧效果“后两张变第 3 张伙伴”会把多数回合压成 前2+后3，单件道具已经近似给出完整构筑答案，现已废弃。

当前效果：前3位至少有2种伙伴时，5号位行动+1。

它鼓励玩家在前三位保留混合颜色，再决定第 4、5 位如何兑现；它不改变任何伙伴，也不会保证后三位相同。千局完整模拟中，风筝在胜局中的出现率为 19.5%，不再是必选构型件。

其他道具审计#

当前 29 件其他道具中，没有第二件会一次改写多个未来位置。月之眼的胜局出现率最高，为 80.6%，但它只在每轮生成一张远镜；高分来自月之眼、水滴、信鸽、灯塔等多件工具组件共同连锁，符合“单件简单、组合爆发”的目标。继续观察它的权重，但不按风筝同类问题处理。

5. 奖励规则#

  • 奖励界面始终允许“跳过补给”。
  • 跳过不获得道具或工具，直接进入下一路段。
  • 五个道具位已满时，选择新道具才进入替换流程；玩家不能被强制替换。
  • 补给改选和跳过互不冲突：玩家可以先改选，再决定领取或跳过。
  • 第一次远行的固定教学候选也允许跳过，教学不能以剥夺选择权为代价。

6. 显示与动效合同#

出牌阶段#

  • 当前价值区不显示 0。
  • 尚未开始结算时显示 Core 提供的初始价值预览。
  • 初始价值会立即反映永久提升、道具、信条、本轮工具和当前已打出伙伴带来的多色加值。
  • 伙伴牌没有固定分数，手牌预制体不保留旧的分数底板或分数文字。

结算阶段#

  1. 显示初始价值。
  2. 第 1 个位置开始前停顿较长，让玩家看清来源。
  3. 此处每次行动依次弹出 +N、×2、失效 等 Core 事件，并更新当前价值。
  4. 此处全部行动完成后，当前价值通过弧形粒子传到下一位。
  5. 越接近 5 号位，行动前和传递后的停顿越短。
  6. 5 号位结束后，最终价值飞向目标进度。

位置间粒子不与数值一比一生成。按当前价值量级使用 5—10 个预制粒子；同色 ×2 用两波粒子表达复制与膨胀。数量、弧高、时长、间隔、缩放和锚点全部由 Prefab / @property 配置。

7. 世界观外皮状态#

机制先使用“初始价值 / 当前价值 / 增加值 / 同色伙伴 / 异色伙伴”的中性语言。当前红帽、黄帽、绿帽、蓝帽、紫帽只是可试玩占位显示；不把“薯团地精、搬货、加工”写进不可替换的机制名。

后续可从以下外皮中选择：

  1. 豆丁队伍：数值表示人数，同色复制队伍，异色加入新豆丁；粒子可直接画成小人剪影，机制映射最直观。
  2. 探险能量：数值表示能量，同色共鸣翻倍，异色补充能量；最抽象，也最容易适配不同场景。
  3. 燃料：目标是积攒足够燃料离开地点；粒子和流动感强，但大数值燃料的叙事合理性较弱。
  4. 光团或灵光：同色共鸣、异色注入；视觉表现好，但角色目标感较弱。
  5. 纯价值赛道：保留 +10 / ×2 门，不解释实体；学习成本最低，世界辨识度最低。

当前建议优先验证“豆丁队伍”和“探险能量”两版视觉草图，再决定正式世界观。

8. 数据与实现边界#

  • Core/JSON 决定规则、数值、条件、奖励合法性和完整 trace。
  • UI 只播放 initialCargo、五个 slotTraces、每次行动事件和最终分数，不重算同色/异色。
  • 稳定伙伴 ID 继续使用 eagle/wolf/turtle/bee/mouse；玩家统称“伙伴牌 / 伙伴手牌 / 所有伙伴”。
  • 30 件道具、8 张工具和 20 条特别状况的玩家文案与效果以运行时 JSON 为准。
  • 当前完整机器可读目录为 potato-goblin-pipeline-content-v0.2.json 的 version 3；旧文件名只为保持已有脚本路径稳定。

9. 当前验证结论#

  • Core 测试覆盖零道具、额外行动、风筝不改牌、初始价值预览、奖励跳过、成长与特别状况。
  • UI 合同覆盖手牌旧分数节点移除、Prefab 参数、奖励跳过与粒子池复用。
  • 千局模拟确认风筝不再接管排列；工具工坊仍是当前最强成熟组合。
  • 当前目标曲线下，纯异色策略的完整远行通关率仍为 0，说明“异色增加值成长”的数值强度尚未通过平衡验收。此问题属于下一轮数值调优，不通过恢复自动改牌解决。
